# VideoCN · 本地视频中文化

Windows 桌面程序：YouTube / 本地视频 → 英文识别 → 中文翻译 → 字幕校对 → 中文配音 → 背景声混音 → MP4。

## 这台电脑上直接打开

双击 `D:\youtubeai\app\VideoCN.exe`，或根目录的「启动 VideoCN.cmd」。当前主程序是约 140MB 的自包含 EXE，无需另外安装 .NET。

1. 在工作台粘贴 YouTube 单条视频链接，或点击「导入本地视频」。
2. 保持「高质量」与「配音前先校对字幕」，点击「开始识别与翻译」。
3. 在「字幕校对 → 字幕文字与生成设置」双击中文修改，可编辑起止秒数，选中一句可播放原视频片段。
4. 点击「生成中文视频」。输出文件夹中会包含 `中文配音.mp4`、`中文配音.srt`、`中文配音.ass` 和 `视频标题与内容简介.txt`。视频完成后，本地模型根据原始标题和最终中文字幕自动撰写中文标题与内容简介；模型临时失败时使用中文字幕生成基础版本，不影响视频导出。“每轴字幕最大字数”可在工作台或字幕校对页设置为 10～40，默认 20；超过时按文字量比例切到后续时间轴。字幕最多显示两行，拆分和换行都不会切开英文单词。
5. 在「字幕校对 → 视频与配音时间轴」预览视频，左右拖动每段中文配音调整位置，再点「按时间轴重新导出」。页面右上角「打开以前的项目」选择旧项目的 `project.json` 即可继续编辑。

「仅下载视频」不需要 AI 模型。关闭「生成中文配音」可制作保留英文原声的中文字幕视频。关闭「配音前先校对字幕」可连续运行整条流程。

## 粘贴 Edge Cookie 表格

1. 在已登录 YouTube 的 Edge 页面打开开发者工具（F12），进入「应用程序 / Application」→「Cookies」，选择 YouTube 的 Cookie 表格并复制完整行。
2. 在 VideoCN 工作台点击「粘贴 Cookie 文本」，按 Ctrl+V 或点「从剪贴板粘贴」。支持制表符分列的文本以及 Markdown 表格，可包含表头。请保留空列；无表头时按名称、值、域、路径、过期时间、大小、HttpOnly、Secure 的顺序读取，后续列忽略。
3. 点击「转换并使用」。软件生成 Netscape Cookie 文件，并自动切换为「使用 Cookie 文件」。随后点击「测试登录」或「仅下载视频」。此方式使用粘贴内容，不需要关闭 Edge 或解密浏览器数据库。

转换器根据提供的 Python 脚本改写为内置 C# 功能，无需单独运行脚本。支持 Session / 会话、ISO 日期、Unix 秒数及 Markdown 转义。无法识别的行会提示行号，不会静默丢弃或覆盖已有文件。

也支持行尾含 `&#x9;` 的富文本副本：自动还原 Markdown 转义（如 `LOGIN\_INFO`），接受完整数据行后单独换行的 `Medium` 等优先级标签。不会对 Cookie 值做 HTML 或 URL 解码，值中的 `||`、`&`、`%3D` 原样保留。请只粘贴表格，不包含聊天说明文字。

文件保存在 `%LOCALAPPDATA%\VideoCN\cookies\imported.txt`；再次成功转换会替换此文件。文件包含登录凭据，请勿分享。原始文本不保存到运行日志，关闭粘贴窗口会清空输入框；「清除」Cookie 文件选择只取消选择，文件仍保留在本机。转换成功只证明格式可用，登录是否有效需通过实际访问测试。

## 首次安装和模型

进入「环境与模型」→「安装 / 修复完整环境」→「下载当前档位模型」。下载工具、Python 环境、GPU 依赖和模型保存在程序目录，不改动系统 Python，也不自动安装常驻服务。首次需要联网及数十 GB 磁盘空间。模型成功缓存后，本地文件的 AI 处理使用缓存；切换到尚未下载的档位会下载对应模型。

| 档位 | 英文识别 | 中文翻译 | 中文配音 |
|---|---|---|---|
| 快速 | Whisper medium | Qwen3 8B 量化 | Qwen3-TTS 0.6B |
| 高质量 | Whisper large-v3 | Qwen3 14B 量化 | Qwen3-TTS 1.7B |
| 精修 | Whisper large-v3 | Qwen3 14B，额外润色一轮 | Qwen3-TTS 1.7B |

### 配音音色

工作台「制作偏好 → 中文音色」另有 6 个标注「微软在线」的普通话音色：晓晓、晓伊、云希、云扬、云健、云夏。通过 [edge-tts](https://github.com/rany2/edge-tts) 使用微软 Edge 在线语音服务，无需 API Key 或登录 Edge；这不是剪映音色包，也不能据此认定为抖音使用量排名。选择在线音色会将待配音文本发送给微软，网络和服务可用性会影响生成。

在线合成不占用本机 GPU，按句请求、最多重试 3 次并缓存为 WAV；中断后复用已完成音频。统一语速、字幕与位置调整沿用原流程；本地风格提示、随机种子、采样温度和双卡设置不控制在线服务。未来重装时「安装 / 修复完整环境」会安装所需 edge-tts 依赖。

剪映/豆包系列的其他音色可查 [火山引擎官方音色列表](https://www.volcengine.com/docs/6561/1257543)，需要按其接口、账户和可用音色接入；当前软件尚未接入该服务。

音色下拉框包含当前 CustomVoice 模型全部 9 种官方音色：Serena、Vivian、Uncle Fu、Dylan、Eric、Ryan、Aiden、Ono Anna 和 Sohee。前五种包含中文原生或中文方言音色；Ryan、Aiden、Ono Anna、Sohee 的原生语言分别为英语、英语、日语、韩语。所有音色都能生成中文，但非中文原生音色可能带有口音。

官方模型与音色更新可在 [Qwen3-TTS Hugging Face 模型集合](https://huggingface.co/collections/Qwen/qwen3-tts) 和 [Qwen3-TTS GitHub](https://github.com/QwenLM/Qwen3-TTS) 查找。CustomVoice 只能使用模型内置的 9 个 speaker 名称，不能通过下载普通 WAV 直接增加。要扩展任意人声，需要使用 `Qwen3-TTS-12Hz-1.7B/0.6B-Base` 和带准确文本的授权参考录音进行声音克隆；要按文字描述创造新音色，可使用 1.7B VoiceDesign，再将设计出的参考声音转成可复用的克隆提示。

CUDA 依赖为 PyTorch / torchaudio 2.5.1 + CUDA 12.4，适配本机 RTX 4070 Ti。WPF 主程序基于 .NET 10，AI 后端为独立 Python 3.12 环境。发行 EXE 包含 .NET 运行时，AI 环境和模型在新电脑上仍需初始化。

## 项目与工作原理

### 视频预览与配音时间轴

编辑页右上角「切换模型并重生成全部语音」可选择 Qwen3-TTS 0.6B、1.7B，或跟随制作质量，并选择默认音色。语音模型单独保存为 `settings.voice_model`，不改变识别、翻译档位；旧项目默认跟随原制作质量。默认保留每段指定的音色，取消该选项可统一替换所有片段音色，人物名保持不变。微软在线音色仍由微软服务合成，本地模型选择仅影响本地音色。

点击弹窗中的「开始重新生成全部语音」后，复用当前中文稿，强制重新生成所有时间轴片段（包括视频已删除区间中的片段），保留开始位置、视频剪切、背景音和音量设置；只更新语音，不自动导出视频。旧项目会先转换为可编辑配音清单；项目文件与配音清单备份为 `project.before-bulk-*.json`、`voice_edit.before-bulk-*.json`，原音频文件保留。开始前把全部片段标为待生成，逐段生成成功后更新音频和模型记录，中断后不会把旧录音当成新模型结果。生成完成可试听，再点「按时间轴重新导出」。

时间尺下方新增紫色「视频轨」。定位播放线后点「切开视频」，或右键视频轨选择「在右击位置切开」；在想删除区间的两端分别切开，再右键中间的视频片段选择「删除此视频片段（连同音频）」。删除区间灰显，可右键恢复，也可点「撤销剪切」。剪切记录自动保存到项目 `video_edit.json`，重新打开可继续；原视频、配音片段和手动摆放位置均保留。

时间轴使用原片时间，灰色区间不会立即收拢，方便准确恢复；播放器计时显示剪辑后的进度与总时长，播放时跳过已删除区间。「按时间轴重新导出」将保留部分无空挡拼接，视频、人声、背景音和导出的 SRT/ASS 同步裁剪并重新计时，不重新生成已有语音。未生成配音的项目可以直接剪辑导出原声视频。跨越剪切边界的声音和字幕也会被裁短，建议在停顿处切开。至少保留一段视频；本次打开期间可撤销，重新打开后可右键恢复灰色片段。若删除片尾，原本超出片尾的配音延长部分也随片尾删除。

多人对话可在配音片段上右键「选择人物音色并重新生成…」，为本段选不同的本地或微软在线音色，并填写可选的人物名（如主持人、嘉宾 A），点击「保存并生成本段」。普通「编辑中文」和新增片段窗口也可选音色；「重新生成本段语音」沿用本段已保存的音色。人物名只用于时间轴标记，同一人物的多个片段需手动选择相同音色，不会自动识别说话人。选择「跟随制作偏好」时使用全局音色；指定音色的片段在整条重新生成时仍保留自己的声音。人物、目标音色和已生成音色随 `voice_edit.json` 保存；更换音色后未生成的片段标为待生成，不会误播旧音色。仅改人物名无需重新生成。开始位置保持不变，片段时长随新语音更新。

编辑页优先给视频预览分配空间，隐藏顶部宣传标题。上下拖动视频下方的绿色分隔条可调整预览与时间轴的高度，双击恢复默认比例；「放大预览」临时收起编辑区域，再点「返回编辑」恢复原布局。音量与背景控制集中在一行，「重新关联原视频」「重新准备兼容预览」位于「更多工具」。进入编辑页或导出完成时收起日志，仍可手动展开查看。

编辑页的「中文人声音量」滑块统一调整全部中文配音，范围 0–200%，默认 100% 保持原音量，0% 静音，可一键恢复 100%。设置自动保存到当前项目，重新打开后恢复；试听与「按时间轴重新导出」均应用该音量，不需要重新生成语音，也不修改配音片段或其位置、语速。背景音仍由背景音轨单独控制。「仅背景」「原片声音」试听不受人声音量影响。超过 100% 时按需缓存放大后的试听片段，使用峰值限幅避免过载；缓存位于项目 `.preview/voice-volume`。音量停止拖动后恢复此前的播放状态，首次放大试听可能短暂准备。

时间尺下方的蓝色轨道是背景音轨。按住鼠标左键拖选范围，然后右键可调整音量和起止秒数、静音该范围、强制使用分离背景，或单独试听背景。右键已有调整可修改或删除，删除后恢复该处默认背景策略。「静音」只影响背景，不影响中文配音；「强制使用分离背景」用于防止空挡误判后混回英文原声。默认边界淡入淡出 0.08 秒，可在调整窗口设为 0–0.5 秒。调整范围不能互相重叠，重叠时请编辑原区域或先删除原调整。

播放器提供「中文＋背景」「仅背景」「原片声音」三种试听模式。「保留背景音」控制整条背景轨开关，「撤销背景调整」撤销本次打开期间的修改。调整即时试听并自动保存到 `background_edit.json`；点击「按时间轴重新导出」应用到成品，不重新生成中文语音。此背景轨开关优先于工作台中的背景保留设置。没有分离背景的项目需先生成一次包含背景声的中文视频。音量百分比相对于原背景策略：人声段采用分离背景的 65%，空挡采用原音轨；强制分离时用分离背景的 65%。降低音量会同时降低该处音乐和环境声。

在配音块上右键可「编辑中文」「重新生成本段语音」「在此段后新增片段」「删除片段」；在时间轴空白处右键可在该位置新增配音。编辑窗口支持只保存文案，或保存后立即生成本段语音。新增/改文案后的片段会标记「待生成」，预览不会误播原来的文案；生成后更新实际长度，开始位置保持不变，允许重叠。右键重新生成只处理该段，沿用制作偏好的音色、风格、种子和统一语速，其他音频不变。

文字、增删和位置自动保存到项目的 `voice_edit.json`，下次打开继续编辑。「撤销编辑」支持本次打开期间的文案、增删与移动操作；删除不会删掉磁盘上的录音。重新生成完成后会重新载入音频，因此撤销记录也会重置。启用时间轴文案编辑后，原字幕表格保留作对照，中文在时间轴中修改；「生成中文视频」也使用这份配音稿。全部待生成片段完成后，点「按时间轴重新导出」更新成品与字幕。

生成中文配音后，在字幕校对页的「视频与配音时间轴」播放原视频画面并试听当前配音布局。点击时间尺跳转，缩放查看细节，左右拖动配音块调整开始位置（以 0.05 秒为步长），或输入精确的开始秒数。选中块后可用左右方向键微调，Shift 加方向键加大步长；支持试听选中段和撤销移动。重叠的配音显示在不同轨道并同时播放，拖动只改位置，不改变语速或时长。「试听原声」切换为原片音轨；配音试听不包含最终的背景声混音。

拖动结束即自动保存 `voice_positions.json`，字幕文字在保存、切换项目或关闭窗口时保存。「按时间轴重新导出」复用现有配音片段更新 `dub.wav`、配音时间表、MP4 与字幕，不调用语音或翻译模型；字幕跟随移动后的配音。若配音超出片尾，导出延长最后一帧以保留完整声音。修改中文文案后需要在「字幕文字与生成设置」先点「生成中文视频」，再编辑新语音的位置。

以前的项目通过「打开以前的项目」选择 `project.json` 恢复。请保留整个项目目录（包括 `segments.json`、`dub_timing.json` 和「配音片段」）；只有成品 MP4 无法恢复每段语音。项目文件夹整体移动后优先使用新目录内的媒体；外部引用的原视频丢失时可点「重新关联原视频」。

视频预览先检查实际编码：AV1、VP9、HEVC、Opus 等不走系统播放器直接预览，而是用 FFmpeg 在项目的 `.preview` 目录生成 H.264/AAC 兼容缓存（画面宽度最多 1280，30 帧/秒）。首次需要等待并显示进度，可以停止；后续打开复用缓存。原视频、音轨位置和最终导出画质不变。仍遇到黑屏可点击「兼容预览」；原声片段弹窗也使用同一缓存。删除 `.preview` 只会导致下次重新准备。

首次预览优先使用 NVIDIA GPU 0 的硬件解码、CUDA 缩放和 NVENC 编码。若当前编码或驱动不支持，则先回退到 CPU 自动多线程解码＋NVENC 编码，仍不可用时改用 CPU 自动多线程转码；不再限制为 2 个线程。进度会显示当前方案、处理倍速和帧数，回退原因保存在 `.preview/preview-transcode.log`。硬件路径参考 [NVIDIA FFmpeg 官方说明](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/ffmpeg-with-nvidia-gpu/index.html)。已完成的旧缓存继续复用，无需重做。

### 中文句末分句与自动对齐

默认勾选「按中文句末分句，自动校准（最多 3 轮）」，默认容差 ±4 秒，也可选 ±1、±1.5、±2、±3 秒。跨原字幕行的中文会合并到 `。`、`！`、`？` 处；一行含多个完整句时会拆分，保留句末引号。没有句末标点的最后一段作为尾句保留，手动设置配音开始的行会成为明确边界。

原 `segments.json` 保留供编辑和作为英文位置参照。生成的完整配音句另存 `sentence_segments.json`，来源备份在 `alignment-source.json`。同一原行内部的句子参照位置按中文文字量比例估算，不是英文音素级强制对齐。对齐报告中的误差比较的是这些来源时间锚点。

每轮先使用实际生成音频的时长，在容差内向前或向后安排位置，同时避免自动配音互相重叠。仍超差时，下一轮只调整相关句子的表达并生成变化的语音，最多做三次配音测量；无改进文案时提前结束。最终保留超差句数更少、最大边界偏差更小的一轮。若仍无法达标，保留全部声音继续导出，报告标出超差，不假称达标。手动位置优先并不参与自动改写。

该模式导出的中文 SRT / ASS 与完整句配音同步。原字幕校对页显示来源行以及对应配音句的位置；最终配音文案、逐句文件、开始/结束误差见 `配音时间表.csv`，详细轮次见 `alignment-report.json`。关闭此选项恢复按原字幕行配音。

### 字数目标

工作台和字幕校对页共用「每秒字数」设置，默认 4，支持 2–8，每次加减 0.5。翻译按每句时长计算目标字数，例如 4 秒 × 4 字/秒 = 16 字，建议范围为目标的 80%–120%。统计不计标点，汉字计 1，英文单词及连续数字各计 1。

新翻译会携带目标范围，并对偏多或偏少的句子做一次额外调整。已有项目在字幕页点「按此字数调整文案」：先备份 `segments.before-rate-*.json`，再处理超出范围的句子。过少时只展开原文已有信息，不添加事实；仍不能满足范围的句子会标为偏多/偏少，不因此阻止导出。取消或失败时已完成的批次会保留，可重新点击处理剩余超标句。

中文配音默认保持生成时的原始速度，工作台的“统一语速”滑块可以在成品导出时统一调整到 0.75x–1.50x。每秒字数仅用于翻译和手动调整文案的长度预算。超出时间窗的声音完整保留，允许与后句重叠；后句仍按原定位置开始，重叠会在配音时间表中标记。调整统一语速不会重新生成语音，文字和音色未改变时复用原始语音缓存。

字速是平均估算：停顿、强调、英语与数字的读法会影响听感，不能保证每一秒说出相同字数。这里控制文案密度和平均发音速度，仍需试听校对。

```text
app/VideoCN.exe           桌面入口
src/VideoCN/              C# / WPF 源码
engine/                  Python 流水线与独立阶段进程
scripts/                 安装、发布和测试视频生成脚本
tools/                   yt-dlp、FFmpeg、Deno、Ollama
.runtime/                独立 Python、CUDA 库与安装缓存

output/<时间_项目编号>/    项目、原音轨、字幕、配音缓存、最终视频

```

每个 AI 阶段在独立进程中运行，结束后释放显存。翻译使用程序自己的 Ollama 子进程，仅监听 `127.0.0.1:11535`，完成后退出；不会使用或卸载你原有的 Ollama 模型。关闭主窗口即退出应用，同时取消播放器和预览准备，统一清理已登记的 Python、配音、翻译、FFmpeg 与预览任务；异步收尾不会再加载项目或启动预览。取消任务或程序意外退出时，Windows Job Object 清理已纳入管理的子进程。清理只针对本次 VideoCN 启动的任务，不按进程名称结束其他软件。

`project.json` 记录已成功完成的阶段；识别和翻译文本保存在 `segments.json`。取消后可从上一个完成阶段继续。翻译按批保存，TTS 按文本、音色和模型缓存。改变字幕只需重新生成变化的配音。原视频采用本地引用，移动或删除原片会影响后续处理。

原始字幕时间轴不能重叠。实际语音结束后连续 2 秒没有说话才分段，空挡不计入文字预算。每段第一句对齐原人声段开头，段内按中文句末分句，手动配音位置优先。导出时不再循环改写文案或按段加速；±4 秒仅用来提示偏差。超长配音可以进入空挡或与后段重叠，由用户调整。若完整声音超过片尾，会延长最后一帧，避免截断声音。

字幕校对页「配音开始 / 秒」独立控制声音位置，留空自动排列；「上次配音位置 / 待调整」显示实际起止时间及提示。修改后再次点击「生成中文视频」即可，文字和音色未变时复用缓存，不重新生成语音。手动位置优先，自动和手动位置都允许重叠，重叠声音会混合，不进行段内限制或缩放。中文句末模式下字幕跟随最终配音时间。项目中也会导出 `配音片段/0001.wav` 等逐句音频、`dub.wav` 完整音轨、`配音时间表.csv`，便于在外部剪辑软件移动音频。当前版本不做声音克隆、说话人区分、口型同步或波形拖拽剪辑。

人声布局保存在 `speech_regions.json`，原音轨按原始位置单独导出到 `人声分段/` 和 `无语音片段/`，对应原片时间见 `人声与空挡时间表.csv`。开启背景声保留时，人声段使用降低音量的分离背景，空挡使用原音轨的音乐与环境声。检测优先使用已有分离人声，否则使用原音轨；检测结果仍可能受低音量人声或音乐影响。

字幕页显示每句所属人声段和有效有声秒数，可点击「重建人声分段与翻译」重新识别。旧项目首次导出也会自动重建：原 `segments.json` 和 `project.json` 先另存为 `.before-speech-*.bak`，再重做识别与翻译。此前人工校对内容保存在备份中，重建后请重新核对。

## 已知限制与排查

- YouTube 可能要求登录验证，匿名下载不保证可用。在工作台「YouTube 登录方式」选择「从 Edge 读取登录状态」，点「测试登录」。资料目录在「Edge 登录设置」中选择（本机为 Default）。打开旧项目会保留本机当前登录方式，继续项目时使用当前登录设置。每次请求会在日志中显示实际使用的登录方式。
- Edge 运行时可能锁定 Cookie 数据库。关闭所有 Edge 窗口后，点击工作台「结束 Edge 后台并重试」：程序结束当前 Windows 会话中残留的 `msedge.exe`，随后重新测试视频访问。检测到 Edge 可见窗口时会提示先关闭，避免丢失页面内容。普通下载不会自动结束浏览器。
- 本机已实测通过新按钮结束 7 个 Edge 后台进程，解除数据库占用；随后下载器返回 `Failed to decrypt with DPAPI`，直接读取登录状态仍未成功。此时可切换到「使用 Cookie 文件」，在环境页选择自行导出的 Netscape 文件，再重新下载。成功读取 Cookie 也不保证站点放行。参见 [数据库锁定问题](https://github.com/yt-dlp/yt-dlp/issues/7271) 和 [Cookie 解密问题](https://github.com/yt-dlp/yt-dlp/issues/10927)。
- 只有选择 Edge 模式才读取浏览器 Cookie，该模式不会导出 Cookie 文本文件。项目只记录所选资料名称；文件模式只记录所选 Cookie 文件路径。两种方式互斥。
- 下载失败时显示简短原因，完整堆栈保存在 `artifacts/run-*.log`，也可展开运行日志查看。环境页提供「更新下载器」。视频和模型下载依赖你本机网络能访问对应站点。
- Demucs 可能残留人声或改变音乐/环境音，不能保证完全分离。
- 12GB 是总显存；其他程序占用显存时可能导致模型加载失败。可使用快速档或 CPU，不会自动关闭其他应用。
- 字幕文件独立导出；默认同时烧录在视频中。成品 MP4 使用 H.264 + AAC，优先 NVIDIA GPU 0 硬件解码和 NVENC 编码；硬件解码不兼容时回退到 CPU 解码＋NVENC，显卡编码仍失败时自动回退 CPU 多线程。原视频分辨率保留，字幕烧录、末帧延长和音频混合仍使用 CPU。进度显示实际方案、处理倍速和帧数，回退原因写入运行日志。NVENC 使用 p3 / CQ 19，CPU 回退使用 medium / CRF 18；两种编码器的质量参数不直接等价。
- 原声预览使用 Windows MediaElement；系统缺少某些解码器时预览可能失败，但 FFmpeg 仍可能正常处理。
- 自动识别、翻译和配音需要人工判断准确性与自然度。仅处理你拥有权利或已获授权的内容。

## 双 GPU 配音任务分配

选择 CUDA 时，配音阶段自动使用前两张可见 NVIDIA GPU；只有一张卡或只有一条未缓存任务时使用单卡，选择 CPU 则仍使用 CPU。每张卡加载独立的完整语音模型，因此各卡都需要足够显存。识别、翻译和背景分离保持原有设备策略。

待生成句子先将少量短句放入共享队列（数量等于本轮工作进程数），让首次完成更快可见；剩余句子按预计文字量从长到短排列，空闲 GPU 自动领取下一句，适应两张卡速度不同的情况。相同文本只生成一次，已有缓存直接复用；完成次序不影响最后字幕和配音排列。语音生成保持统一风格，成品语速由“统一语速”滑块控制，允许重叠。

默认开启“一致性优先”：主语音模型与 Subtalker 两层都使用温度 0.20、Top-P 0.90、Top-K 50 的极低温度随机采样，两张卡共用讲解风格、生成参数和每句起始种子。较宽的候选范围保留结束标记，低温度抑制语气漂移。每个模型显式设为评估模式。此设置兼顾结束标记和语气稳定，但每句仍独立生成，没有共同的参考声音；不同文本和不同型号 GPU 的数值差异仍可能影响听感，不能保证语调完全相同。新版缓存与旧版及普通随机采样模式隔离。

工作台“制作偏好”中的“配音语气与生成参数”可切换一致性优先、调整风格提示词、种子和重复惩罚。关闭一致性优先后才能调整采样温度和 Top-P，此时恢复按文本派生固定种子的普通随机采样。一致性优先开启时使用固定的极低采样值，界面中的温度和 Top-P 不影响生成或缓存。旧项目没有此开关时默认开启。修改生成参数后重新生成中文视频生效；“统一语速”仍只调整所有成品配音的播放速度，无需重新合成原始语音。

进度显示各卡加载、领取、句内实际推理步数、耗时及完成情况。句内进度通过模型 forward hook 观察，最多约每 3 秒上报一次，不改变采样或语速；加载与等待期间每 10 秒刷新耗时，完成百分比仍按完整句子计算。GPU 加载超过 10 分钟未完成，或生成连续 5 分钟未返回实际推理进度时停止等待；CPU 对应期限为 30 分钟。模型详细日志保存在项目的 `tts-workers/`。任一卡失败或超时会停止本轮的配音子进程并保留已完成缓存；取消和关闭程序同样清理子进程。本次仅修改代码，未运行双卡测试或重新生成视频。

任务管理器“性能”页默认可能显示 3D 引擎，CUDA 推理不会反映在那张图上。查看“详细信息”页的“GPU 引擎”列，或在 GPU 性能图表菜单中切换到 CUDA/Compute；程序日志中的“实际设备”才是配音模型的绑定确认。
